# 設計と抽出

[English](../en/architecture.md) · [ホーム](../../README.ja.md)

## 参照元と範囲

読み取り専用の参照元 isekai-sim は、2026-11-25 の調査時点で未コミット変更がなく、
コミットは `982560d0e3dc6d598643ee3b4814e74f7fa0aa28` でした。そのコミットのファイル
から Coordinator と Developer の Skills、役割指示、ネイティブ Worker、ローカルと
GitHub の課題管理、所有権とライフサイクル、チェックポイント、ランナーと受入手順、
適用可能な既存テストを抽出しました。参照元にトラッカー用の Issue テンプレートは
ありませんでした。既存 GitHub 分類を直接変更する旧移行スクリプトと専用テストは、
その移行用に参照元に残します。参照元の認証情報、固有設定、課題状態、研究報告、
実験結果は配布に含めません。

## 構成

| 導入先の場所 | 責務 |
| --- | --- |
| `.agents/skills/` | ネイティブの起動・管理 Skills。 |
| `.codex/agents/adf-worker.toml` | 任意の Worker。専用名を持ち、モデルはセッションや設定から継承。 |
| `agents/tools/` と `agents/docs/` | ライフサイクル、課題管理、実験、診断、還元補助とその手順。 |
| `agents/config.example.toml` | 配布する既定値。ローカルトラッカーを使い、自動再開は無効。 |
| `.copier-answers.yml` | 配布元と導入バージョン。 |
| `agents/config.toml`、`AGENTS.md`、`.codex/config.toml` | プロジェクトが管理する方針・設定。 |
| `agents/research/` とプロジェクト内の報告 | プロジェクトが管理する課題、提案、再現可能な証拠。 |
| `agents/runtime/` | Git 管理外の永続ライフサイクル、所有権、チェックポイント、ログ、成果物。 |
| ホストが管理する設定・認証情報 | 実効権限、トークン、マシン固有の CLI と Codex セッション状態。 |

ローカル課題やレビューの状態は最初の保存時に作成します。トラッカーはプロジェクトが
選び、研究と開発で同じ分類を利用できます。Codex は意味的な判断と承認確認を担当し、
Python ツールは状態遷移、ロック、通知受領、GitHub 操作を担当します。作業ツリーと
ジョブの責任は Developer にあります。完了通知の再開検証は現在の所有者、世代、ジョブ、
受領記録を照合します。

抽出時は固有の識別子、既定の方針、状態の初回作成、Worker の名前とモデル、役割指示を
調整しました。Copier 配布、環境診断、ラベルの事前確認、還元用の選択差分は ADF の
追加機能です。Copier は配布ファイルをそのまま置き、回答ファイル名を展開します。
展開では Tasks、Migrations、信頼設定の拡大、サービスの書き込みを必要としません。
識別子、ローカルの版管理、上流への提案履歴は独立して扱えます。実験的変更を導入先だけに
残すこともできます。

## isekai-sim の将来の移行

所有者が承認した静かな区切りで、現在のコミットと完了ジョブを特定します。ローカル状態、
報告、Git 管理外の実行記録、既存設定をアクセス制限された場所に保存します。別クローンで
ADF の固定リリースを評価します。特に役割、エージェント方針、GitHub ラベル定義、通知設定
の重複を比較します。参照先の GitHub リポジトリ、既存 Issue とラベル、ローカル研究履歴、
ライフサイクル記録を保持します。既存のプロジェクト指示に統合し、Worker 名と実効方針を
確認します。隔離環境で検証した後、実サービスの試験は個別に承認を得ます。レビュー済みの
移行コミットを取り込み、復旧時はその revert と保存したランタイムのバックアップを使います。
