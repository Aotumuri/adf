## 残りのロードマップ

1. 許可された使い捨て Codex プロジェクトで両役割を実行し、Initializer を繰り返し実行する。
   現行ホストで Worker と実効権限を確認する。
2. 指定された GitHub 試験リポジトリで認証済み読み取り、承認されたラベル・Issue の往復、
   許可された提出先へのフォーク・PR を確認する。対象リポジトリと書き込み範囲は所有者が決める。
3. 実運用予定のスタンドアロン CLI で、時間制限付きの同一スレッド通知試験を実施する。
   対象環境で受け入れ試験が済むまで自動再開は無効のままにする。
4. ローカルリリースとは別に公開先と公開範囲を決める。将来の isekai-sim 導入には
   [移行計画](architecture.md#isekai-sim-の将来の移行)を使う。

抽出したライフサイクルを維持しました。導入・更新は Copier に任せ、テンプレートの
Tasks と Migrations は使いません。初期化は Skill と読み取り専用診断、既存の承認付き
ラベル操作で実施します。競合時に通常の Git マージを伴わない未解決インデックスが
発生することを確認したため、更新の失敗対策は別クローンでの隔離としました。
上流還元にはパッチ生成の小さな補助を追加しました。
