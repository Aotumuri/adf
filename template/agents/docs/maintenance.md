[日本語](maintenance.ja.md) · [Operations](OPERATIONS.md)

## Install and inspect

To use `$framework` in the upstream ADF repository, start Codex from `template/`.

Use a trusted versioned ADF URL or absolute local Git path. For an existing
project, start from a clean commit in a temporary branch or clone. Check
collisions against a preview and decide how to integrate each overlapping
file. On reinstallation use the recorded answers and the update workflow.

```sh
copier copy --pretend ADF_SOURCE .
copier copy ADF_SOURCE .
```

Review the installed files and commit the answers. Copier records the source
and tag in `.copier-answers.yml`. Keep those answers generated by Copier.
Use `copier check-update` and review the trusted source's release notes. Agents
are discovered in `.agents/skills/`. Run `$initializer` to integrate with project
policy and test the available capabilities.

## Update and recover

Coordinate a quiet boundary with the Developer and confirm there are no
active jobs or edits. Use a disposable clone of the destination's current
committed state and record the original commit. Keeping preexisting local
customizations committed allows Copier to merge them. Keep uncommitted work
in the original checkout until integration can proceed safely.

```sh
git clone --no-hardlinks "$PWD" "$candidate"
cd "$candidate"
copier update --pretend --defaults --vcs-ref "$tag"
copier update --defaults --vcs-ref "$tag" --conflict inline
git status --short
git diff
git diff --cached
git ls-files --unmerged
```

Resolve each unmerged file using the recorded baseline, upstream changes and
local intent. For reject-file mode review each `.rej`. Check staged and unstaged
changes with `git diff --check` and `git diff --cached --check`, and run the
runtime and project acceptance tests. Review new files too. Check that the
answers name the intended tag. Commit the reviewed update only, then fetch
the candidate via its local path and cherry-pick its commit in the original
checkout at a safe boundary. Confirm project config, state and results there.

Failed update attempts stay in the candidate clone. Start a fresh candidate
from the original commit for retry. If an update accidentally ran in place,
capture the post-failure diff and status, compare to the recorded clean
starting commit, and restore only identified update-owned paths. Quarantine
only verified additions. Preserve unrelated edits and ignored state.
For a committed update, inspect the effect of reverting its commit on a clean
branch and resolve conflicts with later edits. Review any amended framework
Skill only on the next invocation after completing the update.

[Copier update, conflicts and recovery](https://copier.readthedocs.io/en/stable/updating/)

## Contribute

From the downstream root use the Python interpreter with Copier installed.
The helper reads Copier's source, tag and answers, renders the baseline in a
temporary directory, and compares explicitly selected regular files to the
working tree. Assess your edits for reusable improvements, project changes,
experiments and workarounds. Keep private data, project values, credentials,
and research output out of the patch. The helper writes the selected diff
to stdout for local review.

```sh
python agents/tools/contribution.py agents/tools/runner.py > /path/to/adf.patch
git -C "$upstream_checkout" apply --check /path/to/adf.patch
git -C "$upstream_checkout" apply --3way /path/to/adf.patch
```

Use repeatable `--new PATH` for new common files. Removed tracked template paths
produce deletions. The helper maps the literal payload to `template/`. Port
rendered or renamed Jinja paths semantically when needed. Check against the
latest upstream before applying, and reconcile conflicts or apply at the
recorded tag and rebase in an upstream branch if needed. Verify both the
source template and a fresh render. Save the reviewed patch and a proposal
with rationale and test evidence if remote publication is unavailable.
With approval, commit on an upstream or fork topic branch, push it, and use
`gh pr create` for the authorized upstream. Local use and updates continue
independently of the proposal.

Git tags, local merging and answers are Copier features. ADF adds selected
reverse diffs and the documented isolation workflow. ADF releases use
`vMAJOR.MINOR.PATCH` Git tags and bilingual release notes.
